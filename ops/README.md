## Deployment boundary

One API process, loopback bind, one local media store. Rate limits and Socket.IO are process-local. Do not add replicas until shared limiter/session-aware event distribution and shared media storage are designed and tested. No refunds, inventory, cash drawers, physical printer confirmation or durable event delivery.

1. Provision supported Node LTS and MariaDB/MySQL InnoDB. Restrict DB network access to API/migration hosts. Use a dedicated runtime user with only required SELECT/INSERT/UPDATE/DELETE on application schema; no global/DDL/GRANT privileges. Separate migration identity has schema DDL privileges, never used by API. Actual deployment privileges must be inspected by operator; test credentials are not deployment credentials.
2. Use pinned lockfile (`npm ci`, then `npm run db:generate`). Secrets manager or private environment file, mode 0600, service user only. Set NODE_ENV=production, HOST=127.0.0.1, ALLOWED_ORIGIN to exact HTTPS frontend origin, ALLOW_INSECURE_COOKIE=false, independent random CSRF_KEY/READINESS_SECRET at least 32 bytes, DATABASE_URL and dedicated STORAGE_DIR. Never put secrets in CLI arguments, source, logs or URLs sent to clients. Database URL query options are rejected; remote DB requiring TLS needs explicit adapter TLS support before deployment. Prefer local trusted DB transport until supported; never accept plaintext across untrusted networks.
3. Default TRUST_PROXY=false. For example nginx on same host uses TRUST_PROXY=127.0.0.1/32,::1/128. Only comma-separated explicit IP/CIDR values accepted; no true, hop counts, named aliases or /0. Never trust arbitrary networks. Firewall backend port. Proxy must overwrite X-Forwarded-For/Proto, not preserve client-supplied values. Mount test verifies untrusted peers cannot spoof IP/secure status.
4. Configure TLS termination from reverse-proxy.conf.example. Replace host/cert paths; run `nginx -t` before reload. Example not deployed or syntax-verified here (nginx may be absent). Restrict readiness at proxy; internal monitor sends X-Readiness-Key through loopback only. Never log this header. HTTPS secure HttpOnly SameSite=Lax cookie; exact Origin and X-CSRF-Token on mutations. Cross-origin browser uses credentials include. Receipt HTML also sets restrictive CSP; verify headers at actual proxy.
5. Stop writes; take verified encrypted DB + media backup before migrations. Deploy committed migrations with separate migration identity (`npm run db:deploy` with securely supplied DATABASE_URL). Never use db push, migrate reset, or auto-baseline existing schema. DDL is not fully transactional; inspect failed migrations before repair/retry. Generate Prisma client matching installed schema. Start API under service supervisor with restricted service user, persistent writable media directory, bounded private TMPDIR, automatic restart, resource/disk limits and graceful SIGTERM (10 second application deadline). Start only one process. `node --env-file=/private/cafe.env src/server.js` loads config explicitly.
6. Check public /api/v1/health, authenticated readiness over loopback, cookie flags/CORS/CSRF, configured TLS/proxy/client IP, media, login/order/payment/receipt smoke against authorized target. Run `npm run db:validate`, `npm run db:check`; current drift/test scripts are restricted to authorized development target, not production. Never point fixture suites at production. Bootstrap first admin once via stdin CLI documented in root README.

## Backup/restore rehearsal — authorization required

Do not run these steps until owner names source, disposable target, backup destination and authorizes data copy/destruction. Never restore onto live source or silently provision another schema. Commands depend on host DB tool/version and secret-file policy; no credentials in command arguments.

1. Record source engine/version, schema identity, migration table, snapshot time and approved target. Quiesce API writes (media and DB need common cutoff). Keep backup encryption keys separate.
2. With private client option file, take transactional consistent dump using engine-native tool (MariaDB: mariadb-dump --single-transaction --routines --triggers --events; validate table engine assumptions). Capture exit status and encrypted output checksum. Archive dedicated STORAGE_DIR preserving ownership/modes; checksum archive. Never place dumps under public media or repository. Restrict backup account privileges; retention/offsite encryption per owner policy.
3. Restore encrypted dump and media into separately authorized isolated target/storage. Block outbound integrations. Verify exact target before any import; never erase source. Compare migration names, table/row counts, constraints, paid order/payment/receipt relationships, totals, image references and checksums against recorded source cutoff. Test no more than one paid payment/receipt per order and receipt snapshots unchanged. Run scoped read smoke and process shutdown there with explicit target authorization; existing test harness refuses other targets by design, do not bypass it silently.
4. Record real commands (secrets redacted), exits, sizes/checksums, row/count/financial checks, restoration duration/RTO and snapshot age/RPO; retain encrypted evidence with access control. Owner signs off backup retention/restore results before unblocking release. Destroy disposable copy only with approval.

## Logs, storage and incidents

- Application errors expose generic envelope/request ID; operational signal failure logs only event name. Do not enable body/header/SQL debug logs in production. Never log cookies, passwords, CSRF/readiness keys, DB URLs, gateway payloads or private export contents. Nginx example logs URI without query string. Configure supervisor/nginx log rotation, retention, permissions and disk alerts; inspect error logs for URL leakage before rollout.
- Media backups include generated files plus DB references. No credentials in STORAGE_DIR. Export artifacts are private transient files under TMPDIR, mode 0700/0600, deleted on success/error/abort. Crash may leave cafe-export-* directories; remove only stale directories after confirming no live export owns them. Bound filesystem quota/concurrent load externally; production export/PDF capacity remains unverified.
- Payment uncertainty: pause new checkouts, inspect order/payment/receipt and sanitized events, reconcile actual manual transfer independently. Never mark paid from socket/client claims. Pending manual recovery CLI requires active admin password via protected stdin, expected pending and reason; never reverse paid through SQL or recovery CLI. No refunds.
- Compromised account: revoke all sessions/deactivate affected account through active admin, verify no new socket events; preserve audit evidence. Session secret rotation via refresh invalidates old sockets on next publish. If CSRF/readiness secret compromised, rotate config and restart single instance; existing clients refetch CSRF. Never assume CSRF rotation revokes login sessions; revoke sessions separately when needed.
- DB/disk outage: stop writes, preserve logs/backups, verify readiness fails. Fix capacity/connectivity, inspect failed export/media cleanup and reconciliation before reopen. Do not retry unknown financial transactions manually with new keys; exact idempotency replay first.
- Failed migration/release: stop API, inspect migration state and schema with migration identity. Do not blindly roll back DDL or start old code against changed schema. Restore only approved verified backup to approved target under owner decision; retain post-cutoff financial evidence for reconciliation.
